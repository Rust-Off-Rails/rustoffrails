# Generator: `mailer` (`rails generate mailer`)

> **TL;DR**
> - `mailer ReviewMailer new_review` → a pure fn returning an `Email` (HTML + text, absolute links, the shared mail layout), sent via `mailers::deliver_later(&txn, email)` from the model fn.
> - Add a preview to `PREVIEWS`; test with `drain_jobs()` + `sent_emails()`; verify for real through `/dev/mailbox/latest.json`.
> - Mail carrying a token gets its own job that mints the token; never render secrets into an enqueued email.
>
> Read the rest when adding an email.

```
mailer ReviewMailer new_review
```

1. `src/mailers/review_mailer.rs`: `pub fn new_review(cfg: &Config, review: &Review, book: &Book, owner: &User) -> Result<Email, AppError>`. Pure: data in, rendered `Email` out, no DB access. Callers load the data.
2. Templates: `templates/mailers/review_mailer/new_review.html` and `.txt`, with two Askama structs (`NewReviewHtml`, `NewReviewText`). Links are absolute (`cfg.app_url` + `paths::…`). Keep the HTML simple: table layout, inline styles, no external CSS.
   The HTML template `{% extends "mailers/layout.html" %}` (the one mail layout, generated by `new`).
3. Send with `mailers::deliver_later(&txn, email)` from the owning model fn (enqueues `DeliverEmailJob`). If the email is time-limited but holds no secret, use `mailers::deliver_later_until(&txn, email, expires_at)`. If it carries a token (password reset, magic link, invitation), don't enqueue the rendered email at all: write a dedicated job whose args hold only ids, which mints the token, stores its digest and calls `state.mailer.deliver` ([auth](../guides/auth.md), [mailers](../guides/mailers.md#delivering)).
4. **Preview:** add a `Preview { name: "review_mailer/new_review", build: |s| Box::pin(async { … }) }` entry to `PREVIEWS` in `src/mailers/previews.rs`, built from fake data (no DB). It shows up in the dev mailbox's **Previews** tab (`/dev/mailbox/previews`), rendered in the same viewer as real mail ([guides/mailers.md](../guides/mailers.md#previews)).
5. Test: trigger the model fn, `drain_jobs()`, then assert `sent_emails()` has the recipient, subject and a key link.
6. Exercise it for real: run the app, trigger the flow, then `curl -s localhost:3000/dev/mailbox/latest.json?to=<addr>` and follow a link ([dev-tools](../guides/dev-tools.md)). Tell the human they can see it at http://localhost:3000/dev/mailbox.
7. Development always delivers to the dev mailbox (`Mailer::Local`), whatever `SMTP_URL` says. If `EMAIL` in `AGENTS.md` has no production provider yet, tell the human that production mail is only logged until they choose one (set `SMTP_URL`).
