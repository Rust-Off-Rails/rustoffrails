## 0.6.0 (2026-10-13)

Hardening from a 0.3.0 Kanban built by another agent that shipped "green" with three P0 defects. The rule this release follows: **mechanical over prose**. Each fix is a command that proves it, a template, a compile error or a failing check.

- **Fixed: live pages stalled past ~6 tabs.** Browsers allow about 6 HTTP/1.1 connections per origin across all tabs, and each live page holds one or two open (signals + socket). The 7th tab's stream, then its page loads, queued forever. Browsers only speak HTTP/2 over TLS, so `serve` now does **direct TLS with HTTP/2** (`axum-server` + rustls, ALPN `h2`, `APP_TLS_CERT`/`APP_TLS_KEY`), `bin/dev` serves **HTTPS by default** (`bin/dev-cert` makes a local certificate with mkcert or openssl; `APP_TLS=off` for http), and `APP_URL`'s scheme follows. Measured in the reference app: HTTP/1.1 5 of 12 tabs updated; HTTP/2 12/12 and 40/40 ([realtime](guides/realtime.md#many-tabs-stall-http11-vs-http2)). A multi-tab smoke ships with it (`tools/browser-smoke/run.sh live-tabs`).
- **Fixed: the per-user connection cap (8) locked a user out at ~5 tabs** (429 on `/streams`). It's 128 now: sized for tabs, still bounded.
- **Fixed: pages randomly had no htmx and the live badge stayed on "connecting…"** (0.3.x apps). `assets()` picked `"vendor/htmx-"` by prefix from a `HashMap`, which also matches `vendor/htmx-ext-sse-…`; depending on iteration order a page got the sse extension twice and no htmx. Assets now use exact keys (`vendor/htmx-2.`), a test asserts each key matches exactly one file, and the catalog is built once at boot ([frontend-htmx](guides/frontend-htmx.md#assets--cache-busting-kernelassetsrs); CHEATSHEET gotcha 17).
- **Scoped lookups:** with accounts, the public model lookups take the actor (`find_for(db, &user, id)`, `all_for`, `destroy_for`); raw `find`/`destroy` are `pub(in crate::models)`, so a handler can't compile an unscoped call ([models](guides/models.md#scoped-lookups-tenancy)).
- **Tenancy suites for every app with accounts** (not just teams): `tests/app/tenancy_test.rs` requests every id route in `ROUTES` with another tenant's ids (404, or the status an AC specs), and `tests/app/guard_test.rs` fails on unscoped lookups in handlers. Both are templates in [test-standards §4](guides/test-standards.md#4-tenant-isolation-suite-every-app-with-accounts), generated by `authentication`, extended by `scaffold`.
- **`tools/offrails-check`** (also `offrails check`): a POSIX script that fails on an inconsistent header (`ISLANDS: yes` without `UI_LIBRARY`/`web/`, `FRAMEWORK` behind `.offrails/VERSION`), any uncited `AC-…`, a feature without the STRIDE Security table or naming a test that doesn't exist, missing tenancy suites, and unscoped lookups; it warns on a stale `docs/routes.md`. First step of the Definition of Done, in generated CI, `/offrails:check` and `/offrails:doctor`. The framework's CI tests it against a passing tree and a failing fixture per rule.
- **Weak-model rails:** a `NEVER` list atop the app's `AGENTS.md`; a command for every Definition of Done item; **evidence first** (a retry, watchdog, reload cap, `sleep` or raised limit needs the captured failure and a decision line citing it); `docs/decisions.md` lines are superseded, never edited; upgrades reconcile stale decisions.

From Railboard, a Kanban built by headless Claude on 0.5.0:

- **Fixed: a fresh database crashed `serve` at boot** (`no such table: broadcasts`): realtime's pub/sub read its table before the pending-migrations page could render, and `bin/dev` hid it by migrating first. Realtime now starts only once migrations are current (otherwise it waits like the worker and starts after the page's button runs them), and new apps get a fresh-database smoke ([dev-tools](guides/dev-tools.md#pending-migrations), [realtime](guides/realtime.md#kernel-spec-srckernelpubsubrs)). Reproduced and fixed in the reference app.
- **Fixed: a logged-out stream answered 303 to the login page.** `EventSource` can't follow it, so it retried forever, and the stream path became the after-login page. `/streams/` and `Accept: text/event-stream` now get the API flavor: 401, no redirect, no `return_to` ([errors-and-logging](guides/errors-and-logging.md)). Fixed in the reference app.
- Presence: every (re)join gets a snapshot that includes the joiner before any diff; the client buffers diffs until it arrives; reconnects jitter; after a restart, both clients must see each other within backoff + 1 s ([channels](guides/channels.md#the-hub-kernelhubrs)).
- `/dev/sockets`' frame log is specified (types, limits, where frames are recorded, tests) instead of only being promised.
- Islands develop with `vite build --watch`, never the Vite dev server: the dev CSP stays the production CSP, one origin over HTTPS ([frontend-htmx](guides/frontend-htmx.md#islands)). `spa` dev serves the Rust app over http behind Vite's proxy.
- Non-interactive agent runs (`claude -p`, `opencode run`) stop every server they started before finishing, or the run never exits ([cli](cli.md#running-the-app-from-an-agent)).
- `tools/brand/render.sh` works without Chrome: `rsvg-convert` rasterizes the SVGs, else a neutral set from `tools/brand/default/` is copied.
- ts-rs without `.cargo/config.toml`: per-type `#[ts(export, export_to = …)]` and `#[ts(type = "number")]` on every `i64` ([frontend-inertia](guides/frontend-inertia.md)).
- Models rule 8: inserts that can hit a unique index use `on_conflict_do_nothing_on(..)` (SeaORM 2.0.4 `TryInsertResult`), never insert-then-catch ([models](guides/models.md#rules)).

From the website's upgrade to 0.5.0:

- `offrails upgrade [--check] --fw <dir>` checks or upgrades against any release (a tag export, the plugin root), not only `~/.offrails/current`; `--check` exits 0 when current, 10 when an upgrade is due ([upgrade](generators/upgrade.md)).

**App migration** (0.3.x, 0.4.x and 0.5.0 apps; reconcile: *detect* → *final shape* → *converge*, one slice each, green between them):

1. **Run the check.** `sh "$FW/tools/offrails-check"` (before re-vendoring) lists most of the work below. After re-vendoring it's `sh .offrails/tools/offrails-check`, and it must exit 0 at the end.
2. **HTTP/2 + TLS.** *Detect:* `grep -n bind_rustls src/main.rs` finds nothing, or `bin/dev` has no `APP_TLS`. *Final shape:* `Config.tls: Option<TlsFiles>` from `APP_TLS_CERT`/`APP_TLS_KEY` (both or neither); `serve` branches to `axum_server::bind_rustls` (crypto provider installed first, graceful shutdown through a `Handle`); `bin/dev-cert`; `bin/dev` exports the pair unless `APP_TLS=off`; dev `APP_URL` is `https://` with TLS; both vars commented in `.env.example` ([new](generators/new.md) step 4.12, [deployment](guides/deployment.md)). *Converge:* `cargo add axum-server --features tls-rustls` and `cargo add rustls --no-default-features --features aws_lc_rs,std`, then the code. Prove: `curl -sk -o /dev/null -w '%{http_version}\n' https://localhost:<port>/up` prints `2`, and `run.sh live-tabs` passes with 12 tabs.
3. **Connection cap.** *Detect:* `max_conns_per_user: 8`. *Converge:* 128, and the cap test reads the configured value instead of a literal.
4. **Assets (0.3.x).** *Detect:* `grep -n 'vendor/htmx-"' src/kernel/assets.rs`, or a catalog built per request (`AssetCatalog::load` in an extractor). *Final shape:* `ASSET_KEYS` with exact prefixes (`vendor/htmx-2.`, `vendor/htmx-ext-sse-`), the uniqueness test, the catalog in `AppState` (rebuilt per request only in development). *Converge:* per [frontend-htmx](guides/frontend-htmx.md#assets--cache-busting-kernelassetsrs).
5. **Live-region workarounds.** *Detect:* stall watchdogs, reload caps or reconnect retries in `static/app.js` added for tabs that stopped updating. *Converge:* after step 2, reproduce with `run.sh live-tabs`; if it passes without them, remove them and supersede their decision lines. Keep the 0.5.0 `ping` watchdog (it covers dead proxies, not tabs).
6. **Scoped lookups** (`TENANCY` isn't `none`). *Detect:* `offrails-check`'s `[guard]` lines. *Final shape:* the table in [models](guides/models.md#scoped-lookups-tenancy). *Converge:* per model, add `find_for`/`all_for`/`destroy_for`, make `find`/`destroy` `pub(in crate::models)`, let the compiler list every caller, and move each to the scoped fn (tests read through `Entity::find_by_id`, a `reload_<model>` factory helper). Mark lines that are public by spec `// unscoped: <AC id>`.
7. **Tenancy suites.** *Detect:* no `tests/app/tenancy_test.rs` or `guard_test.rs`. *Converge:* copy both from §4, fill `Tenant`, `EXPECTED` (from the ACs), `NOT_TENANT_IDS`, `fill` and `call`, register them in `tests/app/main.rs`, then prove the suite bites (remove one policy check, watch it fail, restore). A failure here is a real cross-tenant bug: fix the handler, never the expectation, unless an AC says the route is shared.
8. **Specs ↔ tests.** *Detect:* `[ac]` and `[security]` lines. *Converge:* write the missing tests; turn prose Security sections into the STRIDE table ([feature-spec](blueprints/feature-spec.md)) with a real test name per threat; tick ACs whose tests pass on both databases.
9. **Header.** *Detect:* `[header]` lines. *Converge:* make `ISLANDS`, `UI_LIBRARY` and `FRONTEND_MODE` describe the code that exists (record a decision if you change a mode), and set `FRAMEWORK` to `.offrails/VERSION` after re-vendoring.
10. **Agent rails.** Add the `NEVER` list from [`blueprints/AGENTS.md`](blueprints/AGENTS.md) to the app's `AGENTS.md`, add `sh .offrails/tools/offrails-check` as the first step of the SQLite CI job ([testing](guides/testing.md#ci)), and reconcile `docs/decisions.md` ([upgrade](generators/upgrade.md) step 8).
11. **Boot on a fresh database** (apps with channels or signals). *Detect:* `serve` awaits `pubsub.start()` (or `cluster::start`) unconditionally. *Converge:* the gated start in [realtime](guides/realtime.md#kernel-spec-srckernelpubsubrs) sharing the worker's `wait_for_migrations`; run the fresh-database smoke.
12. **Logged-out streams.** *Detect:* a logged-out `GET /streams/<x>` answers 303. *Converge:* `/streams/` and `Accept: text/event-stream` take the `Api` flavor in `ResponseFlavor::of`; the stream auth test expects 401 with no `Location` and no `_return_to` cookie.
13. **Presence.** *Detect:* `presence_here_frame` computed before `hub.track`, or a client `Presence` that applies diffs before `here`. *Converge:* per [channels](guides/channels.md#the-hub-kernelhubrs); add the restart convergence test.
14. **Islands** (`ISLANDS: yes`). *Detect:* `localhost:5173` in the dev CSP or `bin/dev`. *Converge:* `vite build --watch` in `bin/dev`, the manifest path in development, and the production CSP everywhere.

- Instant navigation recipe (`guides/frontend-htmx.md`), gotcha from CI: wrap `document.startViewTransition` so a transition skipped by a quick second click doesn't leave unhandled `AbortError` rejections (htmx drops the transition object); make the last boosted click win. **App migration:** apps that adopted the recipe: *detect* `globalViewTransitions` without a `startViewTransition` wrapper in `static/app.js`; *converge* per step 6 of the recipe.

## 0.5.0 (2026-10-13)

Learned from real apps built by other agents and from a real upgrade: an accessibility gate in both themes, robust live regions (from a Kanban built with opencode), a context diet for agents (`CHEATSHEET.md` + a TL;DR on every guide), instant navigation for content sites, and a migration repair convention. rustoffrails.org runs it, with a hosted read-only MCP server at https://rustoffrails.org/mcp.


- Docs: the Postgres compose service is `db` everywhere (`docker compose up -d db`); `fingerprint.sh` ignores a `.git` *file* (worktrees, submodules); the Copilot pointer file has an exact body; `generators/upgrade.md` defines a non-interactive path; the pre-deploy checklist requires green CI on the exact commit.

- Fixes from a real 0.3.0 → 0.4.0 upgrade (bookshelf, via `/offrails:upgrade`): `fingerprint.sh` and vendoring ignore the plugin cache's `.in_use/` marker; the error-page `app.js` snippet is now shown in errors-and-logging; ZAP's "Suspicious Comments" gotcha; the 0.4.0 migration notes' detect lines for #2, #3 and #6 are greppable (and `HX-Push-Url` lives at the end of `error::shape_errors`); the test-harness DB helpers are named (`create_database`, `drop_database`); a macOS ZAP variant; a deterministic first-login transaction test; the upgrade recipe adds a missing "Post-upgrade checks" section.

- **Robust live regions** (`guides/realtime.md`), from a Kanban built with opencode + Muse Spark on 0.3.0: never reconnect by editing `sse-connect` (it leaks `EventSource`s), the ~6-per-origin connection budget (one stream per page), `hx-sync` on live regions, a named `ping` heartbeat event (+ a hidden `sse-swap="ping" hx-swap="none"` observer and a 60s watchdog), a connection-state badge, and the `pageshow` guard in the app layout.
- **Context diet:** a two-page [`CHEATSHEET.md`](CHEATSHEET.md) (stack, layout, naming, DoD, security non-negotiables, the 15 costliest gotchas, commands) is now step 0 of the load order, and every guide and generator opens with a **TL;DR** (what to do, what never to do, when to read the rest). Agents read a full guide only when the task touches it. No app migration.
- **Accessibility gate** (`guides/test-standards.md` §10): axe-core (WCAG 2.2 AA) on every route, in light **and** dark, desktop and mobile; keyboard, motion and form rules; a required `a11y` CI job. Lighthouse checks one color scheme only, which let a light-theme contrast bug through on rustoffrails.org.
- **Instant navigation for content sites** (`guides/frontend-htmx.md`, optional recipe, from rustoffrails.org): View Transitions (cross-document + htmx `globalViewTransitions`) with a fixed header, a CSS-only progress bar via `hx-indicator`, focus to the new `h1` after boosted navigations, a per-deploy versioned stale-while-revalidate service worker (precache, theme-cookie rewrite, offline page, never caching `no-store`/cookie responses), and prefetch on intent. Optional; not for apps with per-user pages.
- **Migrations:** repairing an earlier migration: the repair's `down` restores the predecessor's exact schema, so full rollback works (`guides/migrations.md` rule 2).

**App migration:** none required. If your app's docs or scripts say `docker compose up -d postgres`, use `db`.

Apps with a UI: *detect* no axe suite, or one that runs a single color scheme. *Converge:* add the §10 suite and the `a11y` CI job, then fix what it finds.

Apps with live regions: *detect* `sse-connect` attributes changed from JS, live regions without `hx-sync`, or a stream with no named `ping` event. *Converge* per "Robust live regions"; add the `ping` merge to the stream endpoint and the badge + watchdog to `static/app.js`; add the `pageshow` guard to the layout's script. Apps upgraded from 0.3.0 should double-check 0.4.0 note #5 (the first-login race: a caught unique violation aborts a Postgres transaction).


## 0.4.0 (2026-10-13)

Realtime gets its own wire protocol, **offrails.v1**: typed channels, sequence-based resume after downtime (WebSocket `since`, SSE `Last-Event-ID`), automatic fallback to SSE + POST and then long-polling, and connection security (logout or a password change closes that session's sockets and streams; per-user caps; re-authorized pushes). The security hardening was merged with it and re-verified end to end in the reference app (233 tests on Postgres, ZAP 0 warnings, cargo-deny, gitleaks, browser smoke). Apps can be upgraded from any agent with **`offrails upgrade`** (Claude Code, opencode, Codex) and the agent-neutral **`generators/upgrade.md`**; vendoring now uses anchored excludes from a release tag. The **magic-link** accounts variant is verified by a fresh agent's build (Linkdrop), and its 24 doc findings are fixed below.

### Realtime: the Off Rails Wire protocol (offrails.v1), resume after downtime, transport fallback, connection security

Spec: `guides/channels.md` (protocol, transports, security), `guides/realtime.md` (resume). Verified in the reference app: 223 tests on SQLite and Postgres 18 (39 realtime: conformance, security, all three transports, a 3-node failover), two Playwright specs (a server restart with changes made while it was down; WebSocket → SSE → long-polling), and a two-context Chrome session.

- **Fixed: signals sent while a tab was disconnected were lost** (a deploy, a restart, a blip): live regions silently went stale. Every signal now carries its id; pages render a cursor (`?since=`); reconnects replay what was missed (or `refresh`); `app.js` carries the cursor across htmx-ext-sse's reconnects.
- **Fixed: live regions were dead after a boosted navigation.** The sse extension was loaded in a page's own `<head>`, which a boosted swap never runs. It's in the layout now.
- **Our own protocol, offrails.v1** (replaces the Phoenix v2 array format): negotiated subprotocol, self-describing JSON object frames (`join`/`leave`/`push`/`ping` up; `ok`/`err`/`event`/`presence`/`pong`/`slow`/`bye` down), stable error codes, `bye` before every close, `seq` resume, WebSocket ping control frames instead of app heartbeats.
- **Typed channels:** rooms declare `In`/`Out` serde enums (`#[derive(TS)]` in TS modes); undeclared events are refused before the room runs.
- **Transport fallback:** WebSocket → SSE + POST → long-polling, chosen automatically, remembered per tab, upgraded back when possible. `APP_REALTIME_TRANSPORTS` lists what the server offers.
- **Connection security:** logout, password change and revocation close that session's sockets and streams at once (4401), across processes and nodes; periodic revalidation closes expired sessions (`APP_REALTIME_REVALIDATE_SECS`); pushes re-authorized against current state; per-user caps (connections, topics, joins/min); presence never carries emails; cross-site refused on every transport.
- **`/dev/sockets`** shows each connection's transport and a live decoded frame log (development only).

**App migration** (reconcile, don't re-create; apps without channels do steps 1–3 only):

1. **SSE resume.** Detect `pub struct Signal { pub stream, pub event }` in `src/kernel/pubsub.rs`. Final shape: `Signal { id, stream, event }` (row id), plus `pubsub::high_water` and `pubsub::missed` (realtime.md#kernel-spec). Converge: add the field (set it in `poll_once`), add the two functions; in `channels::stream` take `Query<StreamQuery>` + `HeaderMap`, subscribe first, replay `missed` with ids (or `refresh`), send `ready` with the cursor, add `.id(sig.id)` to live events, skip only exact replayed ids. No migration (the `broadcasts.id` column already exists).
2. **Pages render a cursor.** For every page with `sse-connect`: read `pubsub::high_water(&db)` before the page's data and render `sse-connect="…?since={cursor}"`. Add the `createEventSource` override and the `bye` listener to `static/app.js` (realtime.md#client-side). Inertia/SPA: pass the cursor as a prop and use it in `?since=`.
3. **The sse extension in the layout.** Detect `htmx_sse` inside a template's `{% block head %}`: move the script tag into `templates/layouts/application.html` (after htmx) and delete the block. Add the "every page loads the live-update extension" test.
4. **Channels: switch client and server together** (the formats are incompatible, and old clients now get `bye` `protocol` "subprotocol offrails.v1 required" + close 1002). Replace `kernel/hub.rs`, `kernel/channels.rs` and `static/channels.js` (or `web/src/lib/socket.ts`) per channels.md; convert each room to typed `In`/`Out` enums, `joined(.., since)` returning `Joined`, `handle_in(.., msg: Self::In, out: &mut Outbox<Self::Out>)` returning `Result<Payload, Rejection>`, `out.emit(seq, …)`; rename events on the page (`ch.channel(topic, { since })`, `ch.on("<out event>")`, `ch.push("<in event>")`, errors are `{code, message}`). `cluster.rs` only changes `String` errors to `Rejection`.
5. **Connection security.** `Member` gains `#[serde(skip)] session: Option<i64>`; add `SessionAndUser`; `session::destroy`/`destroy_all_for_user` write the `member:<id>` / `session-ended` signal; `AppState::new` calls `hub.watch_revocations(pubsub.subscribe())` and `hub.log_frames(is_development)`; `Channels` gains `session_valid`; the SSE stream ends with `bye` on `session_ended`. Config: `APP_REALTIME_REVALIDATE_SECS` (60), `APP_REALTIME_TRANSPORTS` (all), in `Config` and `.env.example`.
6. **Fallback transports.** Add the four routes (`/socket/sse`, `/socket/sse/{conn}`, `/socket/poll`, `/socket/poll/{conn}` GET+POST) with `ROUTES` rows, and the handlers calling `kchannels::sse_open` / `relay_post` / `poll_open` / `poll_get`.
7. **Tests:** port `support::Ws` to offrails.v1, add `wire_test.rs` and the resume/session cases in `kernel_pubsub_test.rs`, and `tests/e2e/realtime.spec.ts` (channels.md#testing).

### Upgrading apps from any agent
- **`generators/upgrade.md`**: the upgrade recipe, agent-neutral (Claude Code, Codex, opencode, Cursor). `/offrails:upgrade` now runs it.
- **`offrails upgrade [--check]`** in an app: compares content fingerprints with the installed framework, then launches Claude Code (`/offrails:upgrade`), opencode or Codex with the recipe, or prints the prompt. `offrails new` supports opencode too.
- **Vendoring:** the `rsync` excludes are anchored (`/skills`, `/hooks`, `/evals`, `/brand`…), so `tools/brand/` is kept, and `--delete` removes files dropped upstream. Vendor a **release tag**, never a moving working tree. `.github/` is vendored on purpose, so fingerprints match the release.

**App migration:** none required. Next time you upgrade, vendor with the anchored excludes (`generators/new.md` step 1); `tools/brand/` reappears in `.offrails/`.

### Fixes from the Linkdrop build (a fresh agent, magic-link accounts)
- **`kernel::db::ping`** (for `/up`) and **`kernel::db::drop_idle_test_databases`** (for `test_db_cleanup`): no raw SQL outside the kernel.
- **Panics** render the standalone 500 page via `CatchPanicLayer::custom(error::panic_response)`.
- **Pending-migrations guard** is layered after the fallback, so unknown paths show the page too.
- **`/dev/mailers`** answers 301 explicitly (`Redirect::permanent` is 308).
- **Magic links:** `consume` is one transaction returning user, session and token; first-login user creation uses `ON CONFLICT DO NOTHING` (a unique violation aborts a Postgres transaction; a general rule in models.md); `Option<CurrentSession>` needs `OptionalFromRequestParts` in axum 0.8; token pages send `Cache-Control: no-store` and `Referrer-Policy: no-referrer`. The variant is now verified (168 tests, both databases, real browser).
- **htmx:** a 422 re-render sends `HX-Push-Url: false`, so the address bar keeps the form's URL.
- **Error pages** load `app.js`, so Forward from a 404 works; test-standards §9 checks it.
- **Tests:** `wait_until(what, f: impl AsyncFn() -> bool)`; `enqueued` returns `(job::Model, W)`; per-email rate limits are tested across IPs with `APP_TRUSTED_PROXY` + `X-Forwarded-For`.
- **Docs:** `#[rustfmt::skip]` on `ROUTES`; kernel pages use no `confirm()` dialogs (`data-confirm` pattern for app pages); the e2e package arrives with the first critical flow; port checks with `lsof -sTCP:LISTEN`; direct TLS is added on first use; dates are UTC; guidance for interview answers relayed by another agent.

7. *Detect:* `templates/errors/*.html` without `/static/app.js`. *Converge:* add `<script src="/static/app.js" defer></script>`; extend the browser smoke with Forward from a 404.

## 0.3.0 (2026-10-13)

The open-source release. Rust off Rails is public at https://github.com/Rust-Off-Rails/rustoffrails and installs with one line: `curl -fsSL https://rustoffrails.org/install.sh | sh`.

### One-line install and the `offrails` command
- **`install.sh`** (POSIX sh): shows its plan first, `--dry-run`, `--yes`; Rust via rustup (no sudo); sea-orm-cli, cargo-nextest and cargo-watch as prebuilt binaries via cargo-binstall; a SHA-256-verified framework release in `~/.offrails/<version>` with a `current` symlink; installs the Claude Code plugin when `claude` is present; prints the AGENTS.md prompt for Codex and Cursor. Idempotent, no telemetry. See [INSTALL.md](INSTALL.md).
- **`offrails`**: `new <name> "<pitch>"`, `doctor`, `version`, `update`, `uninstall`.
- New apps also get `.cursor/rules/offrails.mdc` and `.github/copilot-instructions.md`, pointing to `AGENTS.md`.

**App migration:** optional. Add the two agent pointer files above.

### Open source
