# dev-dashboard: checks

What "working and safe" means for the dev dashboard, and the test that proves each item. `tools/security-check.sh` fails when a test named here doesn't exist; `tools/ci.sh dev-dashboard` runs them all on SQLite and Postgres.

The dashboard sees everything the app does: SQL with its parameters, log lines, request paths, the schema, the environment, a GitHub token. Treat each of those as something that must not leave this machine, and the dashboard's actions (traffic, EXPLAIN, running tests) as things an attacker would love to trigger.

The optional **Ask AI** agent is the one feature that sends data off the machine, to a provider the developer configured. Its rows below treat that provider as a third party and everything the app holds as untrusted: the provider gets the previewed first request and then only the results of read-only tools over data the dashboard had already redacted; app data (log lines, email subjects, job errors, paths) may carry instructions, so it is delimited and labelled as data, and the design leaves an obeying model nothing to do but write text and propose buttons; the answer is untrusted text.

## Threat model

| STRIDE | Threat | Control | Test |
|--------|--------|---------|------|
| Spoofing | A cross-site page makes the browser start traffic, run tests, EXPLAIN, seed data or dismiss findings (CSRF) | Every action is a POST through the app's `CsrfLayer`; GETs change nothing | `cross_site_posts_to_every_unsafe_route_are_403`, `the_origin_header_decides_without_fetch_metadata` |
| Spoofing | Someone guesses the production view's password | 16+ characters (refused at boot otherwise); failed tries rate limited per client (the real guard); the compare is of SHA-256 digests with a branch-free fold, best-effort constant time (no early exit, no length leak; the compiler is not forbidden from optimizing it) | `the_production_dashboard_needs_the_admin_password`, `failed_dashboard_passwords_are_rate_limited`, `dashboard_secrets_compare_exactly` |
| Denial of service | Behind a proxy without `APP_TRUSTED_PROXY`, every client shares the proxy's address and one failed-password budget: anyone can lock the admins out for 3 minutes at a time | Known trade-off of keying failures by client address; the misconfiguration is logged once per process when `X-Forwarded-For` arrives untrusted; set `APP_TRUSTED_PROXY=true` behind a proxy | `an_untrusted_forwarded_for_header_warns_once` |
| Tampering | The traffic generator is pointed at another host (SSRF) or at a stream that never ends | It takes paths, never URLs: GET routes from `ROUTES` only, no dashboard, no streams; the host is always the app's own loopback address; caps of 200 req/s, 60 s, 32 in flight | `traffic_only_targets_this_app` |
| Tampering | EXPLAIN runs a write, or runs statements of the attacker's choosing | Only fingerprints the app itself ran, only single SELECTs, never `ANALYZE` (the plan is computed, nothing runs), development only | `explain_runs_for_selects_only`, `only_single_selects_are_explainable` |
| Tampering | The CSRF detector itself changes data | It probes each mutating route with a method that route doesn't have: the CSRF layer answers 403 before routing, and without it the router answers 405; no handler runs | `a_mutating_route_without_csrf_is_spotted` |
| Tampering | A run id or a table name from the URL reaches the filesystem or SQL | Run ids are `[0-9a-z-]` only; catalog SQL interpolates only `[A-Za-z0-9_]` names read from the catalog itself | `run_ids_never_leave_the_runs_folder`, `only_plain_identifiers_reach_catalog_sql` |
| Tampering | Markup in a path, a log line, a SQL statement or API data is rendered as HTML, or a `javascript:` link from the GitHub API | Askama escapes every value (live fragments are rendered by the same templates); only `https://` links from the API become hrefs | `github_links_are_https_only`, `not_found_paths_keep_the_nearest_route_and_a_safe_referrer` |
| Repudiation | n/a: a development tool on the developer's machine; the production view is read-only, so there is nothing to attribute | — | — |
| Information disclosure | The dashboard (SQL, logs, traces, env) is reachable in production | Dev routes are merged only in development (production and test: the router's 404, and nothing is recorded); the read-only view only with `DASHBOARD_IN_PRODUCTION=true` and an admin gate, and without parameters, EXPLAIN, logs, schema, lab, tests or GitHub | `the_dashboard_is_404_in_production_by_default`, `the_production_dashboard_needs_the_admin_password`, `dev_routes_are_404_outside_development` |
| Information disclosure | SQL parameters (emails, tokens, password digests) show on a page | Parameters are kept as type and length ("text (15 chars)"); development keeps the last SELECT's values for EXPLAIN only, never rendered | `sql_parameter_values_never_reach_any_page`, `sql_parameters_are_never_shown` |
| Information disclosure | Secrets logged as fields reach the live tail | Fields named like passwords, tokens, cookies, keys or sessions show as `[redacted]` | `secrets_logged_as_fields_never_reach_the_tail`, `secrets_in_log_fields_are_redacted` |
| Information disclosure | The Config page shows secrets, credentials or the machine's identity | Only the app's own variables (`APP_`, `DATABASE_`, …; not `HOME`, `USER`, `PATH`); values only for an allowlist of never-secret names (`ENV_VALUES_SHOWN`), every other one "set (redacted)" or "not set" (so `SMTP_PASS`, `GITHUB_PAT`, `APP_PEPPER` never show); credentials and query removed from URLs; host name redacted | `config_redacts_secrets_and_credentials` |
| Information disclosure | The production view's trace page shows what the app logged (emails, ids, amounts in events and span fields) | Read-only mode renders spans, timings and normalized SQL only; events and span fields are development-only, on the page, in the inline waterfall (`…/waterfall`) and in the JSON (`…/json`) | `the_production_trace_page_hides_events_and_fields` |
| Information disclosure | The history file (`storage/dashboard/history.sqlite3`) is read by another user of the machine, or holds more than the pages show | Created `0600` in a `0700` folder before SQLite opens it (and its `-wal`/`-shm` set `0600`), where the OS has modes; it holds only what the dashboard already redacted (paths through `redact::path`, secret-looking fields `[redacted]`, normalized SQL without values); in production, no span fields or log events at all; outside the app's database, so a database dump never carries it | `the_history_file_is_private_and_redacted` |
| Information disclosure | Span fields from `#[instrument]` carry a secret or personal data into a trace | Span fields go through the same `[redacted]` rule as log fields; the README's convention is `skip_all` and only fields that are neither secret nor personal; the production view never shows fields | `secret_span_fields_are_redacted` |
| Tampering | A damaged or hostile history file crashes the app, exhausts memory, or is migrated into something else | The file is opened with a `quick_check` and a schema version; anything else is moved aside (`.broken-<time>`) with a warning and a fresh file starts; blobs are versioned and decoded with bounds (inflate capped at 4 MB a chunk, 16 MB a trace; a row that doesn't decode is skipped); strings read back are interned once each, at most 4,096 | `a_damaged_or_incompatible_history_file_is_moved_aside`, `a_chunk_round_trips_through_compression`, `interning_is_bounded` |
| Denial of service | The history file grows without bound | Retention (7 days of minutes, 90 of hours, 14 of traces, 5,000 traces) and a 64 MB ceiling, oldest first, pruned at boot and hourly | `retention_prunes_old_history_and_caps_the_size` |
| Information disclosure | The CPU sampler runs in production, or exposes data | Started only in development (refused in production and tests, whatever the env says), Linux and macOS only; its page is development-only (404 in the production view); stacks are function names from the binary, no arguments or data | `the_profiler_never_runs_outside_development` |
| Spoofing | A cross-site page pauses the profiler | `POST /dev/dashboard/profile/toggle` goes through the app's `CsrfLayer`, like every action | `cross_site_posts_to_every_unsafe_route_are_403` |
| Information disclosure | A past Ask AI investigation opened by another browser | A finished run is what the history lists, already redacted, to anyone who can open the history (the same gate); a live run's page and stream stay its starter's | `every_listed_investigation_opens`, `a_run_stream_is_bound_to_its_browser` |
| Information disclosure | The GitHub token leaks | Sent only in the `Authorization` header (marked sensitive); never on a page, in `Debug`, or in the log; network calls only when the page is opened, cached 60 s | `the_github_token_is_never_shown_or_logged` |
| Information disclosure | A token in a URL (an emailed sign-in link's path, a query string in a referrer or a CSP report) is stored and shown | Recorded paths go through the host's `kernel::redact::path` (token routes and long random segments become `[redacted]`); referrers are cut to a path (this app) or a host (another site); report URLs lose their query string and fragment | `not_found_paths_keep_the_nearest_route_and_a_safe_referrer`, `csp_reports_are_collected_without_query_strings` |
| Information disclosure | The schema browser shows customer data; the routes explorer shows the checkout's absolute path | The browser reads the catalog and counts only, never rows; handler sources are app-relative | `the_schema_browser_never_shows_row_data`, `route_sources_are_app_relative` |
| Information disclosure | Dashboard data stays in a shared or back/forward cache | Every response of both routers is `Cache-Control: no-store` | `every_dashboard_response_is_no_store` |
| Denial of service | Traffic (or a scanner) grows the dashboard's memory without bound | Every ring and map is fixed-size: routes keyed by `ROUTES` pattern with one `(unmatched)` bucket, 500 fingerprints, 300 + 100 traces with per-trace caps (2,000 spans, 1,000 statements, 100 events, the rest counted) and an 8 MB byte budget, 1,000 log lines, 100 404 paths, 100 CSP reports, 2 h of minutes (older ones on disk), 15 minutes of CPU profiles at 1,500 stacks each | `the_dashboard_stays_within_its_memory_bound`, `self_time_gaps_critical_path_and_truncation`, `hot_functions_aggregate_self_and_total` |
| Denial of service | The middleware slows every request | A few µs in release (measured); one atomic check when off; the dashboard's own pages aren't recorded | `the_middleware_overhead_is_small` |
| Denial of service | Method spans slow a request that opens many | A debug span is never built outside development (the filter is `info`); in development each costs a few µs (measured); past 2,000 per trace they are counted, not kept | `method_spans_are_cheap`, `self_time_gaps_critical_path_and_truncation` |
| Denial of service | The load lab or the test runner takes the machine down | Hard caps (rate, duration, in flight; skipped requests are counted, never queued); one run at a time; the memory spike frees itself; one test run at a time | `traffic_only_targets_this_app`, `the_memory_spike_is_freed`, `the_run_tests_button_runs_in_the_background_with_progress` |
| Denial of service | GitHub's rate limit is burned by page views | Answers cached for 60 s; a used-up limit stops calls until its reset; 4 s timeout | `github_rate_limits_and_timeouts_are_respected` |
| Information disclosure | Ask AI sends customer data, secrets or credentials to a third party (the AI provider) | Contexts are built on the server (`ai_context.rs`) from already-redacted data only: SQL fingerprints with parameters as type and length, route patterns and redacted paths, log lines and failure output through `kernel::redact::text`, schema names, types and counts; never a row, an env value, a cookie, a header, a token or the GitHub data; the read-only view sends less (no parameters, log events or span fields, four tabs only) | `ai_contexts_carry_no_rows_parameters_or_secrets`, `the_schema_browser_never_shows_row_data` |
| Information disclosure | Ask AI sends something the developer never saw | Preparing a context stores it under a random id for 15 minutes and the panel previews the exact first request (system prompt, page data, every tool's schema; headers, the key's value never shown); a run starts only from that id, and nothing is sent when it is missing, expired or belongs to another tab or item. After that, only tool results go out, each shown live as a step and kept in the history | `only_the_previewed_context_is_sent`, `a_run_stream_is_bound_to_its_browser` |
| Information disclosure | The AI key leaks: on a page, in the log, in a trace, in the dashboard's recorded requests, in `Debug` | Env only (`DASHBOARD_AI_API_KEY`), never stored; sent in one header marked sensitive (`x-api-key` or `Authorization`); the Config page shows "set (redacted)"; `DashboardAi`'s `Debug` redacts it; the dashboard's own routes aren't recorded; failures log the error kind, never the request | `the_ai_key_never_reaches_logs_traces_pages_or_recorded_requests`, `config_redacts_secrets_and_credentials` |
| Tampering | SSRF through the provider address: the dashboard is made to call an internal host, or a redirect carries the request and key elsewhere | The address comes from `DASHBOARD_AI_BASE_URL` only (no request can choose it), checked at boot: `https://`, or `http://` to localhost, 127.0.0.0/8 or ::1 (a local model), no credentials, query or fragment; redirects are never followed; 5 s connect, 90 s total, 256 KB answer cap | `the_ai_base_url_is_https_or_loopback`, `the_ai_client_handles_errors_timeouts_oversize_and_redirects` |
| Tampering | Prompt injection through app data: a log line, an email subject, a job's error or a path tells the model to read `.env`, call tools, run things or send the key elsewhere | Every tool reads; nothing mutates (an action is a validated proposal rendered as a button the human clicks); tool results go back inside `<app-data … trust="untrusted">` with any closing delimiter defused and a "not instructions" line, the page data inside `<dashboard-data>`, and the system prompt says never to follow instructions in either; `read_source` refuses dotfiles and anything outside its allowlist; the key is only ever in a header; links in the answer stay text | `a_prompt_injection_in_app_data_has_no_side_effect_and_leaks_nothing`, `proposed_actions_are_validated_and_render_as_buttons` |
| Tampering | An Ask AI item id reaches SQL or the filesystem | Item ids are validated per tab (a trace number, a fingerprint, a plain identifier, an 8-hex finding id) and only select something the dashboard holds; table pages look names up in the catalog's own list | `ai_items_are_validated_per_tab`, `only_plain_identifiers_reach_catalog_sql` |
| Information disclosure | Tool results send customer data, secrets or another sample's private data to the provider | Tools return the dashboard's already-redacted shapes, capped at `MAX_TOOL_CHARS`: fingerprints (parameters as type and length), redacted log lines and errors with email addresses masked, schema without rows; the mailbox as subjects, masked addresses, sizes and link hosts (never a body, a link's path or a code); jobs as worker, state, attempts and redacted errors (argument names and types, never values); GitHub as workflow names, conclusions and counts; the app snapshot as scalars without `config`, URLs or assets; the read-only view gets no source, logs, schema, EXPLAIN, mail or jobs | `every_tool_answers_within_its_cap`, `other_samples_pages_send_shapes_never_bodies_or_values`, `ai_contexts_carry_no_rows_parameters_or_secrets` |
| Information disclosure | `read_source` is used to read secrets or files outside the code (path traversal, `.env`, a symlink, a huge file) | Only `src/`, `migration/`, `templates/`; only `.rs`, `.html`, `.sql`; relative paths of plain characters with no `..` and no dotfile or dot-folder; the canonical path must stay inside the allowed folder (no symlink out); 512 KB and 160 lines per call; each line through `redact::text`, and the string literals of a line that names a secret replaced; `search_source` walks the same allowlist and skips symlinks and dot entries | `read_source_stays_inside_the_allowlist` |
| Tampering | XSS through the model's answer or its citations (an injected log line makes the model reply with markup, a `javascript:` link, or a citation whose id carries markup) | The reply is parsed into a Markdown subset of text blocks (`ai::render_in`) that Askama renders escaped; a citation tag becomes a link only for a known kind with a validated id (digits, hex, a plain identifier, a route that exists in `ROUTES`, a chart series from an allowlist within the last day) pointing at the dashboard's own pages; a `[file:…]` citation is code, never a link; guides link only from an allowlist; proposed `open_page` targets are same-site dashboard paths of plain characters | `a_model_reply_with_markup_renders_inert`, `citations_link_only_to_validated_dashboard_pages`, `proposed_actions_are_validated_and_render_as_buttons`, `the_markdown_subset_parses_into_blocks` |
| Information disclosure | The overview's AI briefing sends the app's (redacted) data to the provider on a page view, without a click | Only with `DASHBOARD_AI_PROACTIVE=true` (opt-in), in development, once per process, through the same budget and preview-built context as a click; otherwise it is a button and nothing is sent | `the_command_center_briefs_without_a_key_and_with_one` |
| Spoofing | A cross-site page, or another browser, makes a run spend more (Continue) | `POST …/ai/runs/{id}/continue` goes through the CSRF layer, only for the browser that owns the run, only for a finished answer that was cut, and counts against the per-minute rate and the day's budget | `a_cut_answer_continues_in_the_same_run`, `cross_site_posts_to_every_unsafe_route_are_403` |
| Denial of service | Ask AI spends without bound, or the budget runs out after a few agent runs | Daily questions, tokens and (optional) dollars per process from `DASHBOARD_AI_*`, validated at boot; per-run token, step and time caps; older tool results cut before each call and the prefix marked for the provider's cache; every refusal names the limit and the variable that raises it | `ai_budgets_come_from_the_environment`, `the_daily_dollar_cap_stops_the_day_and_says_how_to_raise_it`, `older_tool_results_are_cut_and_the_prefix_is_cached`, `an_agent_run_stops_at_its_budget_and_says_so` |

| Tampering | The attack simulator is aimed at another host, or its traffic is mistaken for a real attacker's | Paths only (the host is this app's own address, as the traffic generator's); at most 400 requests a run, one run at a time, 50 a second; every simulated client address is a TEST-NET one (192.0.2.x, 198.51.100.x, 203.0.113.x); development only (404 in production) | `the_attack_simulator_lights_up_every_detector`, `dev_routes_are_404_outside_development` |
| Spoofing | A client claims another address to hide or to frame someone (the simulator's header) | A simulated address is honored only with this process's random secret, in development; elsewhere the address is the socket's, or the rightmost `X-Forwarded-For` hop behind `APP_TRUSTED_PROXY=true` | `a_simulated_client_address_needs_the_simulators_secret`, `client_addresses_are_truncated_in_production` |
| Information disclosure | Client addresses (personal data), session cookies, accounts or query strings sit in the dashboard or reach Ask AI | Production keeps and shows an address only as its network and a keyed hash (`203.0.113.x #a1b2c3`; SipHash with a per-process random key); sessions and accounts only as keyed hashes; user agents as a family; query strings inspected in flight, never kept (only which pattern matched); paths redacted | `client_addresses_are_truncated_in_production`, `security_detectors_fire_on_synthetic_streams` |
