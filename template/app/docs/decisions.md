# Decisions

2026-10-16: the mailer, dev mailbox, job queue, jobs dashboard, accounts and realtime are not in the base template; each is a part (`cargo offrails add-part <name>`, from `.offrails/template/parts/`), added when the product needs it (because a blog without background jobs shouldn't carry a job queue, and each part is proven by adding it to this blank app)
2026-10-16: shared files carry inert `samples: <anchor>` comments where samples insert their wiring (because `cargo offrails add-part` applies a part's wiring at anchors, and the same anchors tell an agent where each line goes)
2026-10-16: croner is not a dependency yet (because only recurring jobs use it; the jobs part adds it)
2026-10-16: kernel pages declare their own stylesheets and scripts on `Chrome` (`.stylesheet()`, `.script()`), and the kernel layout links exactly those (because a page whose CSS lived in app.css rendered unstyled: kernel pages never load app.css)
2026-10-16: asset keys are exact paths unless they end in `-` or `.` (a versioned vendor prefix), and the catalog is a BTreeMap (because prefix matching on HashMap order picked the wrong file)
2026-10-16: in development a localhost APP_URL follows the port and scheme actually served (`config::resolve_app_url`); a non-local APP_URL (a tunnel) is kept (because a stale APP_URL in .env sent every emailed link to another port)
2026-10-16: errors under /api and for event streams are JSON (`{"error": "not_found"}`), every 503 carries Retry-After, and 5xx responses are logged with their request id (errors-and-logging.md#response-mapping)
2026-10-16: the theme switch (System / Light / Dark) lives in the kernel header; the choice is the `offrails_theme` cookie (`system|light|dark`, not HttpOnly, SameSite=Lax, a year), the server renders `<html data-theme>` from it on kernel pages, app pages and error pages, `POST /theme` is the no-JS fallback (same-site `return_to` only), and admin.js switches instantly and dispatches `themechange` (because views.md#dark-mode asks for a server-rendered `data-theme`; the name is namespaced so it never collides with an app's own `theme` cookie, and it stays out of the production HttpOnly backstop because a script can't overwrite an HttpOnly cookie)
2026-10-16: kernel CSS defines each color token once with `light-dark()`, and `:root[data-theme]` sets `color-scheme`; no prefers-color-scheme color blocks (because those ignore the switch)
2026-10-16: request URIs reach logs only through `kernel::redact` (`{token}` segments of `TOKEN_ROUTES`, long random segments and secret query values become `[redacted]`), and the log filter caps `tower_http::csrf` at debug whatever RUST_LOG says (because emailed links carry tokens in the path, and the CSRF layer traces raw paths)
2026-10-16: development listens on 127.0.0.1 unless `APP_BIND` says otherwise (a dev container sets `APP_BIND=0.0.0.0`); production keeps 0.0.0.0 (because /dev tools have no login, and anyone on the same network could open them). Deviates from `.offrails/cli.md`, which says `serve` binds 0.0.0.0
2026-10-16: development refuses a `Host` that isn't localhost, 127.0.0.1, [::1], `*.localhost`, `APP_URL`'s host or an `APP_ALLOWED_HOSTS` entry, with a 403 page saying how to allow it (`kernel::hosts`, like Rails' HostAuthorization) (because DNS rebinding reaches /dev same-origin, past the CSRF layer)
2026-10-16: an unset APP_ENV still means development (so `cargo run` works) but logs a warning at every boot (`Config::boot_warnings`) (because on a server it means a missing setting, and development mounts /dev tools)
2026-10-18: an unset APP_ENV refuses to boot with a message naming the fix; `.env` is read first so a set-up checkout still runs (reverses the 2026-10-16 line: a warning in a log nobody reads is not a gate, and development mounts /dev and /admin/jobs without a login)
2026-10-18: `APP_TRUSTED_PROXY_HOPS` (default 1) picks which `X-Forwarded-For` hop is the client (because behind two proxies the rightmost hop is a proxy, and every user then shared one rate-limit key: ten failed logins by anyone locked everyone out)
2026-10-16: the parts' tracing layers are added as `Option<Vec<…>>`, `None` when empty (because an empty `Vec` layer answers `Interest::never()` and silenced every log line of an app with no part layers)
2026-10-16: `kernel::redact::text` redacts free text (URL credentials, token segments and secret query values, `password=…` pairs, long random words) for error text that is stored or shown later (because failure messages quote the URL that failed)
2026-10-17: page scripts load from the app layout (`static/app.js`; parts at `samples: app head`) and bind by delegation on `document`, never in a page's head block or on DOMContentLoaded (because links are boosted: a boosted click runs nothing from the next page's `<head>`, and the sign-in page's password Show button was dead after clicking through to it). Guarded by `smoke_test.rs` and `.offrails/tools/browser-smoke/smoke-boosted.mjs`
2026-10-18: the look lives in `brand.toml`, rendered by `cargo offrails brand` into `assets/brand.css`, `src/brand.rs` and the favicon set; `gray-*` is the brand's neutral and `indigo-*` an alias of `primary-*` (because parts and generated templates are written in the default palette and must follow the brand without edits); colors that fail WCAG AA are refused, never written
2026-10-18: `layouts/application.html` is the shell every layout extends (one `<head>`, skip link, overlays, dev footer); pages pick top nav, sidebar, marketing, auth or docs with `{% extends %}` (because boosted links swap `<body>` only, so every layout must share the scripts in `<head>`)
2026-10-18: UI is built from `templates/components/ui.html` (Askama macros over the component classes in `assets/app.css`, behaviors delegated in `static/components.js`), shown at `/dev/components` (development only); modals are native `<dialog>`s and confirmations use the layout's dialog, not `window.confirm` (because a few words of template are reviewable and consistent, and long class lists drift from the brand and dark mode one copy at a time)
